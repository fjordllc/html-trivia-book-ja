# 第3章 なぜ Web は HTML を選んだのか

帳票を配るなら PDF、文書を共同編集するならワープロ、リンクをたどって読むページなら HTML。同じ文章を運ぶ形式でも、守りたいものが違います。

ここでは PDF や Word を、現在の読者に分かりやすい比較対象として使います。1989 年の Web 提案、1990 年の最初の実装に対して、PDF の登場は 1993 年です。当時の開発者がこの三つを候補に並べて HTML を選んだ、という史実の再現ではありません。

## 3.1 版面を保つか、読む環境へ合わせるか

PDF は、ページ番号、改ページ、図版の位置などを固定して配る用途に向いています。印刷する申請書なら、同じ欄が同じ位置にあることに価値があります。

HTML は、見出しや段落の役割を伝え、文字の折り返しや配置を受け手の表示環境へ委ねます。画面幅や文字サイズが変わっても、文章を順に読み、リンク先へ進めるようにする。その代わり、どの環境でも同じ位置で改ページすることは中心の目標ではありません。

PDF にもリンクや構造情報を持たせられます。違いはリンクの有無だけではなく、固定したページを優先するか、文書の構造をもとに表示を組み立てるかにあります。

## 3.2 編集の作業物と公開する文書

Word のようなワープロは、一つの文書を書き、修正し、コメントや変更履歴を交わす作業に向いています。HTML でも編集アプリを作れますが、HTML 自体は編集手順や承認の流れを定める形式ではありません。

一方、Web では URL で文書を指し、HTTP で取得し、HTML で内容の構造とリンクを伝えます。ワープロ文書を Web で配布することもできますが、それだけでこの役割分担の代わりになるわけではありません。

たとえば、装置の運転記録から測定結果へ進めるページは、次のように書けます。

```html
<h1>運転記録</h1>
<p>今日の測定結果は <a href="beam-status.html">運転状況</a>を参照してください。</p>
```

文章が何行に折り返されても、「運転状況」が別文書への参照であることは変わりません。[第2章](chapter2.md)の CERN の課題に対して、こうした構造を異なる計算機で共有できることが重要でした。

## 3.3 形式を選ぶときに守りたいもの

実務では、形式の優劣より、受け手が何をするかから選びます。

| 目的 | 選択肢の例 | 確認する点 |
| --- | --- | --- |
| 決まった版面を印刷する | PDF | 改ページ、用紙サイズ、文字の再現 |
| 原稿を共同で編集する | Word などの編集環境 | 変更履歴、共同編集、受け手の環境 |
| 公開してリンクで読ませる | HTML | 見出し構造、移動、画面幅や入力方法への対応 |

申請一覧を HTML で提供し、提出用の帳票を PDF で出力する設計も自然です。一つの形式にすべての役割を押し込む必要はありません。

HTML が Web の基盤になった背景には、接続された文書を環境差を越えて共有するという問題設定があります。この性格を押さえると、受け手のブラウザが文書を読み取って DOM を作る過程も、単なる表示の裏方以上のものとして見えてきます。次章では、その過程をソースと並べて観察します。
